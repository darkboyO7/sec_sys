## 2. Build an explainable assessment-priority engine

Implement a deterministic prioritization service that ranks eligible assessment work using evidence-backed signals.

- Asset criticality.
- Confirmed finding severity.
- Verified exposure changes.
- Evidence freshness.
- Time since last successful assessment.
- Assessment coverage gaps.
- Failed or overdue independent retests.
- Relevant monitoring changes.
- Compliance-control failures or unknown states, if supported.
- Previous assessment failures and repeated infrastructure problems.
- Explicitly configured assessment deadlines.
- Cost and expected execution duration, if reliable estimates exist.

Do not invent risk values or assume that missing observations prove a security problem.

Each priority decision must include:

- Computed priority or score.
- Input factors and their source references.

- Relevant uncertainty and missing data.

## 3. Enforce eligibility before ranking

Priority must never override authorization.

- The assessment request is authenticated and authorized.
- The target belongs to an explicitly permitted assessment scope.
- Explicit exclusions take precedence over inclusions.
- Required approvals remain valid.
- The selected adapter and operation are permitted by policy.
- The target has not become ineligible since the request was created.
- Required configuration and credentials, if any, are valid and securely available.
- The operation complies with the platform's defensive, non-disruptive boundaries.

Revalidate eligibility immediately before execution, not only when creating the job.
