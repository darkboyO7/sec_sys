## 1. Governance & Classification Framework

In accordance with Part II, Section 4 of the VAPT System Master Directive, every platform capability across all 26 core architectural phases and 46 process capabilities is strictly classified using the following evidence-based status definitions:

- **VERIFIED:** The capability is completely implemented in production code, backed by reproducible automated tests (unit, integration, or system acceptance), and passes with exit code 0.
- **IN PROGRESS:** Work is actively underway; code changes are being authored, tested, and reviewed.
- **IMPLEMENTED:** The code exists in the repository, but full verification or test automation is pending.
- **BLOCKED:** The capability is architecturally ready and code-certified, but execution is blocked by a physical external dependency, absent infrastructure, or external network reachability constraint.
- **DEFERRED:** A deliberately postponed capability with an explicit architectural rationale and documented acceptance impact.
- **NOT STARTED:** No meaningful code implementation exists.
