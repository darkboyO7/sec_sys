# Evidence-Backed Security Reporting, Verifiable Exports & Reproducible Assessment Results Matrix (Prompt 32)

## 1. Overview
This matrix documents the design, verification, and enforcement mappings for Prompt 32 — Evidence-Backed Security Reporting, Verifiable Exports & Reproducible Assessment Results.
Every report artifact generated by the platform is grounded in persisted database entities and verified cryptographic evidence payloads—never fabricated from frontend-only assumptions or ungrounded AI summaries.

## 3. Cryptographic Provenance & Safety Semantics

1. **Deterministic Manifest Provenance:** Every assessment report manifest computes a 64-character SHA-256 provenance digest covering `project_id`, `assessment_id`, lifecycle status, finding counts, severity breakdown, and evidence counts.
2. **Safe Export Bundles:**
   - Archives are packed with standard Unix tarball structures without execution bits or host usernames.
   - Every file within the archive has a matching entry in `manifest.json["files"]` and `sha256sums.txt`.
3. **Non-Destructive Bundle Verification:**
   - Inspection mode is strictly `validation_only`.
   - Bundles are never auto-merged, auto-remediated, or permitted to overwrite current authoritative database findings.
